# HU-01: Registro e inscripción de un nuevo nodo institucional (IES)

**Estado:** terminada y desplegada en AWS (API + formulario web + pruebas + documentación). El equipo autorizó avanzar a HU-02.
**Cobertura:** RF-01, RF-13. **Estimación original:** 3 puntos. **Prioridad:** Alta.

> Como representante de una nueva universidad quiero diligenciar el formulario de inscripción en el portal de la Red Federada para solicitar el alta como nodo federado emisor y consultor de información.

## 1. Qué se hizo y por qué

Una universidad abre el formulario `/registro-nodo`, escribe NIT, nombre, dominio web y correo de contacto, y envía la solicitud. El sistema crea el nodo con estado `PENDIENTE_APROBACION` y un código `IES-XXXXXXXX`. Todavía no tiene clave de API: eso lo hace el administrador en HU-02.

- **API:** `POST /api/v1/nodes/register`, pública (quien se registra aún no tiene credenciales).
- **Formulario web:** `GET /registro-nodo`, accesible y adaptable a celular, con validación en pantalla, mensajes por campo y pantalla de confirmación con el código del nodo.
- **Un NIT no se puede registrar dos veces** (evita solicitudes duplicadas).
- **Persistencia:** repositorio en memoria (por defecto, para pruebas y desarrollo) o DynamoDB (`REPOSITORY_BACKEND=dynamodb`, tabla `NodesTable`).

## 3. Cómo ejecutarlo y probarlo

### 3.1 Levantar la app final
```powershell
.\run-app.cmd                       # Windows
bash run-demo.sh --app              # macOS / Linux (o: python scripts/run_demo.py --app)
```
Cuando salga `APP FINAL LISTA`, abre **http://127.0.0.1:8001/registro-nodo**. Detener: `Ctrl+C`.

### 3.3 Pruebas desde la API
```powershell
curl.exe -i -X POST http://127.0.0.1:8001/api/v1/nodes/register -H "Content-Type: application/json" -d "{\"nit\":\"899999063-3\",\"name\":\"Universidad Nacional de Colombia\",\"domain\":\"unal.edu.co\",\"contact_email\":\"admisiones@unal.edu.co\"}"
```
- Primera vez: `201` con `{"node_id":"IES-…","status":"PENDIENTE_APROBACION",…}`.
- Repetido: `409`. Con datos inválidos: `422` con la lista de campos.
- En Thunder Client, carpeta **App final**: «HU-01 Registrar nodo (201)», «HU-01 Datos inválidos (422)», «HU-01 NIT duplicado (409)» (ejecutar en ese orden, con el entorno **Local** y `appUrl` = `http://127.0.0.1:8001`).

## 5. Decisiones
- El endpoint es público; el anti-abuso en AWS lo da el límite de tasa del API Gateway.
- NIT único con `Scan` en DynamoDB: catálogo pequeño, evita crear un índice. Se revisa si crece.
- El formulario se sirve desde la misma app (mismo origen): sin CORS y con CSP estricta (D-16, D-19).
- La app final reutiliza el sistema de diseño de la demo por copia, sin importar entre carpetas (D-17).
- El código del nodo `IES-XXXXXXXX` se muestra una sola vez en pantalla; el seguimiento del estado llega con HU-02.
