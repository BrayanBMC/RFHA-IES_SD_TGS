# HU-02: Aprobación de un nodo y emisión de su API Key

**Estado:** terminada (API + pantalla de administración + pruebas). Aprobada por el usuario para avanzar junto con HU-03 a HU-05.
**Cobertura:** RF-02, RF-14. **Prioridad:** Alta.

> Como administrador general de la red quiero revisar las solicitudes de las universidades y aprobarlas para que reciban una clave de API y puedan participar.

## 1. Qué se hizo y por qué

El administrador abre `/admin`, escribe su clave y ve las solicitudes. Al pulsar **Aprobar**, el nodo pasa de `PENDIENTE_APROBACION` a `ACTIVO` y el sistema genera una **API Key** (`rfha_…`). La clave se muestra **una sola vez**; en la base de datos solo se guarda su huella **SHA-256**. Si se pierde, no se puede recuperar (habría que emitir otra).

- **Quién es el administrador:** el servidor compara el encabezado `X-Admin-Key` con la variable de entorno `ADMIN_KEY` (brecha B2). Sin `ADMIN_KEY` configurada, nadie puede administrar.
- **Por qué SHA-256 y no PBKDF2 para la API Key:** la clave la genera el sistema con 256 bits de azar, así que no se puede adivinar; un hash rápido basta y permite buscar el nodo por la huella.
- **Lista pública de nodos activos** (`GET /api/v1/nodes/active`): solo código y nombre. La usa el portal del estudiante (HU-04) para elegir la universidad destino.

## 3. Cómo probarlo (en pantalla)

1. Registra una universidad en `/registro-nodo` (HU-01).
2. Abre `/admin`, escribe la clave de administrador (`ADMIN_KEY` de tu `.env` en local) y pulsa **Cargar solicitudes**.
3. Pulsa **Aprobar** en la fila de la universidad. Aparece la **API Key**. Pulsa **Copiar API Key**: la necesitarás en `/panel-nodo` (HU-03).
4. Casos de rechazo: clave de administrador equivocada → «Clave de administrador incorrecta.»; filtro **Solo nodos activos** → la universidad aprobada ya no tiene botón.

API: `POST /api/v1/admin/nodes/IES-XXXXXXXX/approve` con `X-Admin-Key: …` → `200` con `api_key`; otra vez → `409`; código inexistente → `404`; sin clave → `403`.

## 5. Decisiones
- D-28: la clave del administrador general es una variable de entorno (`ADMIN_KEY`), sin Cognito (B2).
- El administrador de cada universidad usa su `X-Node-API-Key` (HU-03).
- No se implementó «rechazar solicitud»; no está en los criterios. Se puede añadir si el equipo lo pide.
