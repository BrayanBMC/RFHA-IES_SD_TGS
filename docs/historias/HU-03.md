# HU-03: Carga y sincronización de historiales académicos

**Estado:** terminada (API + panel del nodo + pruebas).
**Cobertura:** RF-03, RF-15. **Prioridad:** Alta.

> Como representante de una universidad activa quiero cargar los historiales de mis estudiantes para que puedan ser consultados dentro de la red con su consentimiento.

## 1. Qué se hizo y por qué

Una universidad aprobada (HU-02) envía `POST /api/v1/node/sync-records` con su `X-Node-API-Key` y un lote de hasta **100 estudiantes**. El sistema:

1. **Identifica al nodo por su API Key** (calcula el SHA-256 y busca el nodo). El `node_id` del dueño sale de ahí, **nunca del cuerpo**: un nodo no puede escribir datos de otro.
2. **Valida** código estudiantil, cédula, nombre, programa, estado académico, asignaturas (nota de 0 a 5 o vacía si está en curso, semestre `AAAA-S`).
3. **Calcula el estado de cada asignatura:** `APROBADA` (nota ≥ 3,0), `REPROBADA` o `EN_CURSO`.
4. **Firma el historial:** `digital_signature_hash` es el SHA-256 del JSON canónico (claves ordenadas) del registro sin la clave ni la firma (brecha B6). Cualquier cambio posterior se detecta al recalcularla.
5. **Guarda con upsert** por `node_id#student_id` (brecha B12): si el estudiante ya existe, se reemplaza.
6. **Siembra la clave del estudiante** (campo `password`, opcional): solo se guarda su huella PBKDF2-SHA256 con sal. La usa el portal del estudiante (HU-04). Si en una nueva carga se omite, se conserva la anterior (brecha B1).

## 3. Cómo probarlo (en pantalla)

1. Con una universidad aprobada y su API Key (HU-02), abre `/panel-nodo`.
2. Pega la API Key y pulsa **Cargar ejemplo** (2 estudiantes ficticios con clave `Clave-2026-A` y `Clave-2026-B`).
3. Pulsa **Sincronizar historiales**: «Recibidos 2, Nuevos 2, Actualizados 0».
4. Pulsa **Sincronizar** otra vez: «Nuevos 0, Actualizados 2» (upsert, sin duplicar).
5. Rechazos: API Key equivocada → «API Key incorrecta o nodo no activo.»; en el JSON cambia una nota a `7` → error `422` indicando el campo.

## 5. Decisiones
- D-29: PBKDF2-SHA256 de la biblioteca estándar con 100 000 iteraciones (el número va dentro del hash). Es menos que las 600 000 que recomienda OWASP; se eligió para que una carga de 100 estudiantes quepa en el límite de 30 s de API Gateway con una Lambda de 1 GB. Subirlo es cambiar una constante.
- La cédula identifica al estudiante en el portal; el `student_id` sigue siendo la clave del expediente (brecha A5/B3).
- La búsqueda por cédula usa `Scan` con filtro: el catálogo es pequeño y evita crear un índice (se revisa si crece).
