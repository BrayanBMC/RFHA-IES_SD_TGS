# HU-05: Revocación del consentimiento (lista negra)

**Estado:** terminada (API + portal del estudiante + pruebas).
**Cobertura:** RF-08, RF-16. **Prioridad:** Alta.

> Como estudiante quiero anular una autorización que di, para que esa universidad deje de poder ver mi historial aunque el token todavía no haya vencido.

## 1. Qué se hizo y por qué

Un JWT no se puede «apagar» desde afuera: sigue siendo válido hasta que vence. Por eso cada token tiene un `jti` y el sistema mantiene una **lista negra**: al revocar, el registro del token en `TokensTable` pasa a `revoked = true`. `verify_token` consulta esa marca en cada verificación, así que el token deja de servir **al instante**, sin esperar las 24 horas.

- **Ver las autorizaciones** (`POST /api/v1/student/tokens/list`): cada una con universidad, fecha de creación, vencimiento y estado `ACTIVO`, `REVOCADO` o `EXPIRADO`.
- **Revocar** (`POST /api/v1/student/tokens/{jti}/revoke`): solo el dueño del token. Es **idempotente** (revocar dos veces no falla). Si el `jti` no existe o es de otra persona, la respuesta es la misma 404, para no revelar tokens ajenos.
- **TTL:** el registro lleva `ttl` = vencimiento del token; DynamoDB lo borra solo después de que ya no sirve (brecha B5: la lista no crece sin límite).
- Ambas operaciones usan `POST` con cédula y clave en el cuerpo para que la clave no quede en direcciones ni registros.

## 3. Cómo probarlo (en pantalla)

1. En `/portal-estudiante`, ingresa y genera dos autorizaciones (HU-04).
2. En **Tus autorizaciones** verás dos filas «Activo». Pulsa **Revocar** en una: pasa a «Revocado» y su botón desaparece; la otra sigue activa.
3. Intenta de nuevo con la clave equivocada: no puedes ver ni revocar nada (401).
4. (HU-06/07 usarán esto) Un token revocado ya no abre el historial: lo demuestra `test_un_token_revocado_deja_de_ser_valido`.

## 5. Decisiones
- D-31: la lista negra no es una tabla aparte: es el campo `revoked` de `TokensTable`. Menos tablas y se consulta con la misma lectura que ya hace falta para validar el token.
- Un token firmado correctamente pero sin registro en la tabla se trata como no válido (por ejemplo, si la tabla se reinició).
