# HU-07: Bloqueo de consultas no autorizadas

**Estado:** terminada (misma ruta que HU-06; pruebas por cada rechazo).
**Cobertura:** RF-06, RF-10. **Prioridad:** Alta.

> Como estudiante quiero que ninguna consulta sin mi permiso vigente obtenga mi historial, para controlar quién ve mis datos.

## 1. Qué se hizo y por qué

Los controles viven en `GET /api/v1/federated/academic-history/{student_id}` y se aplican **antes** de buscar el expediente. El primero que falla corta con **403** y no toca los datos:

| # | Control | Mensaje (403) |
|---|---|---|
| 1 | API Key de la universidad que consulta | «API Key de nodo ausente, inválida o nodo inactivo» |
| 2 | Token presente | «Falta el token de consentimiento del estudiante» |
| 3 | Firma y vigencia (HS256, `exp`) | «El token es inválido» / «El token expiró» |
| 4 | Destino del token (`aud`) = universidad que consulta | «El token no fue emitido para esta universidad» |
| 5 | Lista negra (`jti` revocado en HU-05) | «El token fue revocado por el estudiante…» |
| 6 | Token del mismo estudiante que la URL (`sub`) | «El token no pertenece a este estudiante» |

Un token robado sirve de poco: solo abre el historial de **un** estudiante, **desde una** universidad, durante 24 horas, y el estudiante puede revocarlo al instante. Cierra la brecha B4 (claims) y B13 (consultante autenticado). Reutiliza `verify_token` de HU-04/05.

## 2. Archivos
Mismos que HU-06 (`federated.py`, `tokens.py`) y `tests/test_hu06_07_federated.py`. La pantalla `/consulta` muestra el código HTTP y el motivo del rechazo.

## 3. Cómo probarlo (en `/consulta`)
1. **Sin token:** deja el token vacío → 403.
2. **Token alterado:** cambia una letra → 403 «inválido».
3. **Revocado:** en `/portal-estudiante` revoca el token y repite → 403 «revocado».
4. **Otra universidad:** usa un token generado para la universidad B con la API Key de la A → 403 «no fue emitido para esta universidad».
5. **Otro estudiante:** cambia el código del estudiante → 403 «no pertenece».
6. **API Key equivocada** → 403.
